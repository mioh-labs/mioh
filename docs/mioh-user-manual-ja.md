# mioh ユーザーマニュアル

バージョン 0.14.3-014

対象: mioh-universal for macOS
改訂日: 2026年9月24日

## 1. miohについて

miohは、動画内のモザイク領域を検出し、復元モデルで処理して元動画へ合成するmacOS用アプリです。動画の分割、復元、検出、エンコード、メモリ管理、通常動画・VR動画の再生を一つの画面から操作できます。

処理はMac上で実行されます。入力動画を外部サービスへアップロードする機能はありません。処理対象について必要な権利と許可を確認し、適用される法令を守って使用してください。

### 動作環境

- Apple Silicon搭載Mac
- macOS 26以降
- Core AIモデルはmacOS 27以降
- 大きな動画では十分な空き容量を持つ高速な一時ディスクを推奨
- 長時間処理中は電源へ接続し、ほかのGPU・MPS処理を控えることを推奨

`mioh-universal`の配布DMGにはモデルの重みを同梱していません。アプリをインストールした後、同梱ツールで重みをダウンロード・変換します。macOS 27以降ではCore AIモデルも作成できます。macOS 26ではMPS版BasicVSR++とCore MLモデルを使用します。「Universal」はこのモデル導入方式の名称であり、Intel Mac対応を意味しません。

## 2. インストールと起動

1. [miohのv0.14.3-014リリース](https://github.com/mioh-labs/mioh/releases/tag/v0.14.3-014)から`mioh-universal-0.14.3-014-unsigned.dmg`を入手します。
2. `mioh-universal.app`を`Applications`へドラッグします。
3. 次節のモデルダウンロードと変換を完了します。
4. Applicationsフォルダからmiohを起動します。
5. macOSが初回起動を確認した場合は、入手元を確認してからシステム設定の「プライバシーとセキュリティ」で起動を許可します。

この配布物はApple Developer IDによる公証済み配布物ではなく、ビルド時にアドホック署名されています。入手元を確認したうえで使用してください。

### 2.1 モデルのダウンロードとインストール

ターミナルで次を順番に実行します。DMGを取り外した後でも、アプリに同梱されたスクリプトを実行できます。アプリを起動している場合は終了してから作業してください。

```zsh
APP=/Applications/mioh-universal.app
TOOLS="$APP/Contents/Resources/model-tools"
zsh "$TOOLS/download-mioh-models.zsh" --app "$APP"
zsh "$TOOLS/convert-mioh-models.zsh" --app "$APP"
```

ダウンロードした重みと変換後のモデルは、どちらも`mioh-universal.app/Contents/Resources/models`に保存されます。ダウンロードは個々のSHA-256を照合し、失敗した項目を最後に一覧表示します。失敗した場合はネットワーク・空き容量・エラー内容を確認して、同じコマンドを再実行してください。正常な既存ファイルは再ダウンロードされません。

標準の復元モデル、検出モデル、Real-ESRGAN x2/x4のみを取得する場合は、ダウンロードコマンドに`--minimal`を追加します。通常実行では、SwinIRやNomosなどの追加ROIエンハンサーも取得します。追加モデルも使いたい場合は`--minimal`を指定しないでください。

macOS 26では変換コマンドが自動的にCore MLのみを作成します。macOS 27以降ではCore MLとCore AIの両方を作成します。目的を限定する場合は、変換コマンドに`--coreml-only`または`--coreai-only`を付けられます。Core AIの標準出力は持ち運べる`.aimodel`で、実行前に`.aimodelc`へコンパイルすることは必須ではありません。

変換に使うPython 3.12と必要な変換スクリプトはアプリ内に同梱されています。古いリリースの`runtime`フォルダをコピーしないでください。モデルの変換には時間とディスク容量が必要です。処理中はスリープを避け、外付けディスクを使用している場合は取り外さないでください。

### 2.2 モデル導入の確認とアプリ更新

まず重みと変換結果の存在を確認します。macOS 26ではCore AIの2行は不要です。

```zsh
APP=/Applications/mioh-universal.app
MODELS="$APP/Contents/Resources/models"
test -s "$MODELS/lada_mosaic_restoration_model_generic_v1.2.pth"
find "$MODELS" -maxdepth 1 -name '*.mlpackage' -print
find "$MODELS" -maxdepth 1 -name '*.aimodel' -print
find "$MODELS/basicvsrpp-v1.2-variable-coreai.aimodel" \
  -maxdepth 1 -name '*.aimodel' -print
```

可変長BasicVSR++のCore AIコレクションは11個の`.aimodel`で構成されます。miohを起動し、「復元」「検出」タブのモデル一覧に変換済みモデルが表示されることを確認して、短い動画で試してください。ファイルの存在だけでは推論の成功までは確認できません。

モデルはアプリの中にあるため、新しい`mioh-universal.app`でアプリを置き換えるとモデルも置き換わります。更新前に必要なモデルを別の場所へバックアップするか、更新後に上記2つのスクリプトを再実行してください。既存のモデルを新アプリへ移す場合も、必ず同じバージョンの変換ツールで動作を確認してください。

### 2.3 ソースからmioh Universalをビルドする

開発者向けの手順です。Apple Silicon Mac、XcodeとCommand Line Tools、`uv`、Python 3.12、十分な空き容量が必要です。macOS 26以降でアプリをビルドでき、Core AI変換・動作確認にはmacOS 27以降と対応するXcodeが必要です。以下はリポジトリのルートで実行します。

```zsh
cd /path/to/mioh
xcodebuild -version
xcrun --find swiftc
uv python install 3.12
uv venv .venv-coreai --python 3.12
uv pip install --python .venv-coreai/bin/python \
  -e '.[apple-coreml]' 'coreai-torch==0.4.2' \
  'torch==2.11.0' 'torchvision==0.26.0'
```

既に`.venv-coreai`がある場合は作り直さず、`coreai`、`coremltools`、`torch`がその環境に入っていることを確認してください。ビルドスクリプトはこの環境と`uv`のPython 3.12をアプリへ同梱します。ほかの環境を使う場合は`LADA_STANDALONE_PYTHON_ENV`と`PYTHON_SOURCE`で指定できます。

PDFを更新してからUniversalビルドを実行します。PDFがないとDMG作成は失敗します。

```zsh
uv run --no-project --python 3.12 --with reportlab \
  scripts/docs/build_mioh_manual_pdf.py
zsh packaging/macOS/standalone/build_universal_app.sh
```

成果物は`build/macos-standalone-universal/mioh-universal.app`と`build/macos-standalone-universal/mioh-universal-0.14.3-014-unsigned.dmg`です。ビルドはモデルなしの配布物を作成します。モデルを使うMacでは、アプリのインストール後に2.1節のダウンロード・変換を行ってください。ビルド用スクリプトはアプリ本体とCore AIヘルパーを別々のmacOSターゲット向けにコンパイルします。

ビルド後は次を確認します。`hdiutil verify`の成功に加え、アプリ内のPythonと2本のモデルツールが存在することが重要です。

```zsh
APP=build/macos-standalone-universal/mioh-universal.app
DMG=build/macos-standalone-universal/mioh-universal-0.14.3-014-unsigned.dmg
test -x "$APP/Contents/Resources/runtime/bin/python3.12"
test -f "$APP/Contents/Resources/model-tools/download-mioh-models.zsh"
test -f "$APP/Contents/Resources/model-tools/convert-mioh-models.zsh"
codesign --verify --deep --strict "$APP"
hdiutil verify "$DMG"
shasum -a 256 "$DMG"
```

リリース作成・公開まで行う場合は、`docs/mioh-universal-build-release-runbook.md`の追加検証と公開チェックリストも実施してください。この節はビルド手順であり、リリースへのアップロードは行いません。

## 3. 最短の使い方

1. 「基本」タブの「入力」で動画または動画フォルダを選びます。
2. 「出力」で保存先フォルダを選びます。
3. 初回は「自動最適化」「FP16」をオンのまま使用します。
4. 「復元」タブでは、まず合成効果を初期値のままにします。
5. 「出力」タブで`hevc-apple-gpu-balanced`を選びます。
6. 右下の「開始」を押します。
7. 「ログ」タブで進捗とエラーを確認します。

初回は短い動画で動作と画質を確認してから長編を処理してください。

## 4. 基本タブ

### ファイル

| 項目 | 説明 |
| --- | --- |
| 入力 | 単一動画または動画を含むフォルダを選択します。 |
| 出力 | 完成動画の保存先フォルダです。 |
| 一時フォルダ | 一般的な一時ファイルの保存先です。初期値は`/tmp`です。 |
| FFmpeg一時フォルダ | 分割・結合・エンコード用一時ファイルの保存先です。空欄なら自動選択します。 |
| mioh一時フォルダ | 検出・復元用一時データの保存先です。空欄なら自動選択します。 |

外付けSSDを一時フォルダに指定する場合は、処理中に取り外さないでください。空き容量が少ないディスクや低速なネットワークドライブは避けてください。

### 実行

| 項目 | 推奨 | 説明 |
| --- | --- | --- |
| デバイス | MPS | Apple GPUを使用します。CPUは動作確認向けです。 |
| FP16 | オン | メモリ使用量を抑え、通常は高速化します。 |
| 自動最適化 | オン | 解像度と環境から安全な設定を選びます。 |
| 既存結果を上書き | オフ | 同名の出力を保護します。 |

## 5. 分割タブ

長編動画を複数セグメントへ分けて処理し、最後に結合します。

| 項目 | 初期値 | 説明 |
| --- | --- | --- |
| ネイティブ並列数 | 1 | 連続する時間バッチを1〜10レーンで処理します。レーン数を増やすほど復元モデルと中間フレームのメモリを消費します。 |
| 実行方式 | Swiftネイティブ | デコードから書き出しまでSwiftネイティブ経路で処理します。 |
| 分割方法 | 個数 | 分割数または1セグメントの秒数を指定します。 |
| 分割数 | 4 | 動画全体を指定数に分けます。 |
| 長さ | 60秒 | 秒数方式で使うセグメント長です。 |
| 結合エンコーダー | copy | 再エンコードせず結合できる場合に高速です。 |
| 処理済みセグメントを削除 | オフ | 完了後に中間成果を削除します。 |
| 一時ファイルを保持 | オン | 障害時の再開や調査に利用できます。 |
| 強制的に再分割 | オフ | 既存セグメントを使わず、最初から分割し直します。 |

まずネイティブ並列数1を推奨します。処理が安定している場合だけ増やしてください。4〜10レーンは高メモリのMac向けです。スワップが増えた場合は並列数を下げてください。

## 6. 復元タブ - モデル

### 復元モデル

| モデル | 用途 |
| --- | --- |
| basicvsrpp-v1.2 | MPS版。macOS 26で使用できる標準の高品質モデルです。 |
| basicvsrpp-v1.2-coreai-t90 | macOS 27用。長い時間窓を持つ通常処理向けモデルです。 |
| basicvsrpp-v1.2-coreai-t36 | macOS 27用。速度・メモリとのバランスを取るモデルです。 |
| basicvsrpp-v1.2-coreai | macOS 27用。短い時間窓でリアルタイム寄りの処理に使用します。 |
| カスタム | 対応するモデルファイルまたはモデルフォルダを指定します。 |

### クリップと時間方向の設定

| 項目 | 初期値 | 説明 |
| --- | --- | --- |
| 最大クリップ長を指定 | オフ | オフの場合は`-1`を渡すのではなく、モデルに適した長さを自動選択します。 |
| 復元チャンク数を指定 | オフ | オフの場合はメモリ状況に応じて内部処理単位を自動調整します。 |
| Temporal overlap | 8 | 隣接チャンク間で重ねるフレーム数です。境界のちらつきを減らします。 |
| クロスフェード | オン | 重複区間を滑らかに合成します。 |

Temporal overlapは8から20を目安にします。増やすと境界が改善する場合がありますが、処理時間が増えます。20を超える値は通常、改善量が小さくなります。

## 7. 復元タブ - 合成

これらは復元モデルの出力に対する後処理です。復元モデルそのものを再実行する設定ではありません。値を一度に大きく変えず、短い比較動画で一項目ずつ確認してください。

| 項目 | 範囲 | 初期値 | 効果と注意 |
| --- | --- | --- | --- |
| シャープ | 0-2 | 0 | 輪郭を強調します。高すぎると白縁・黒縁やノイズが出ます。 |
| ディテール | 0-1 | 0 | 局所コントラストを増やします。圧縮ノイズも強調する場合があります。 |
| 境界フェザー | 0-3 | 1 | ROIと元画像の境界をぼかして段差を抑えます。大きすぎると境界がにじみます。 |
| テクスチャ | 0-1 | 0 | 元画像の中周波成分を復元結果へ戻します。元のモザイク模様を戻す場合があります。 |
| スムージング | 0-1 | 0 | 粒状感や強すぎる質感を抑えます。高すぎると塗り絵状になります。 |
| エフェクト倍率 | 1x-4x | 1x | ROIをBicubicで拡大し、上記効果を適用してAreaで元サイズへ戻します。復元モデルの推論倍率ではありません。 |

安全な開始点は、シャープ0、ディテール0、テクスチャ0、スムージング0、境界フェザー1、エフェクト倍率1xです。シャープを試す場合は0.1から0.3程度、スムージングは0.1から0.2程度から確認します。

### ROIエンハンサー

ROIエンハンサーはBasicVSR++の後に追加する空間超解像モデルです。

| 項目 | 説明 |
| --- | --- |
| 方式 `none` | 追加エンハンサーを無効化します。BasicVSR++による復元自体は実行されます。 |
| realesrgan | Real-ESRGAN系モデルを使用します。 |
| mewzoom | MewZoomモデルを使用します。 |
| swinir | SwinIRモデルを使用します。 |
| spandrel | RealPLKSR・SPAN・CompactなどSpandrel対応モデルを使用します。 |
| モデル | 選択した方式に対応する組み込みモデルだけを一覧表示します。フォルダボタンからカスタムモデルも選べます。 |
| 倍率 | 選択モデルに合わせて2xまたは4xへ自動設定します。必要な場合は手動変更もできます。 |
| 強度 | 0なら結果へ混ぜません。1ならエンハンサー結果を最大限使用します。 |
| タイル | 0で自動・無分割です。メモリ不足時だけ32刻みで指定します。 |

ROIエンハンサーは存在しない細部を推測して追加するため、強度を上げると色味、肌の質感、輪郭が不自然になることがあります。0.2から0.4程度を開始点にしてください。

Real-ESRGAN方式では、軽めの2倍処理を行う
`Real-ESRGAN x2plus — Core AI (2x)` と、より強い4倍モデルを選べます。
x2plusは入力256px・出力512pxの固定形状モデルで、macOS 27以降のCore AI対応環境に表示されます。

## 8. 検出タブ

| モデル | 特徴 |
| --- | --- |
| v2-coreml | 互換性を優先した初期値です。 |
| v3.1-fast-coreml / v4-fast-coreml | 速度優先です。 |
| v3.1-accurate-coreml / v4-accurate-coreml | 精度優先です。 |
| vr-v2-accurate-coreml | VR素材向けです。 |
| v2 / v3.1 / v4 / VRの各`-coreai`モデル | macOS 27のCore AIを使うFP16検出モデルです。 |
| カスタム | 対応モデルを指定します。 |

VR検出モデルの重みはUniversal版やGitHub Releaseには同梱せず、モデルダウンロードツールでも取得しません。VR検出モデルの変換は、利用者が正規に保有する重みを自分で配置した場合のみ任意で実行されます。VR動画の再生機能には、この検出モデルは不要です。

「空検出先読み」は一時的に検出が途切れたとき、同じシーンの追跡を継続するフレーム数です。大きくすると短い検出抜けに強くなりますが、別の領域へ誤って追従する場合があります。

「顔モザイクを検出」は顔のモザイクも処理対象へ含めます。通常はオフです。

## 9. 出力タブ

### エンコード設定

| プリセット | 特徴 |
| --- | --- |
| hevc-apple-gpu-balanced | AppleハードウェアHEVC。速度と容量の推奨初期値です。 |
| h264-apple-gpu-balanced | 互換性を重視するH.264ハードウェアエンコードです。 |
| h264-cpu-uhq | 高品質ですが低速です。 |
| h264-cpu-fast | CPU H.264の速度優先です。 |
| av1-cpu-uhq | 高圧縮ですが非常に時間がかかります。 |

「自動」は入力と環境に任せます。「プリセット」は上表から選びます。「カスタム」はFFmpegのエンコーダー名を直接指定します。

| 項目 | 初期値 | 説明 |
| --- | --- | --- |
| ビットレート倍率 | 3.0 | 入力動画のビットレートに掛ける倍率です。 |
| MP4 Fast Start | オフ | MP4のメタデータを先頭へ配置し、ストリーミング開始を速くします。 |
| Quality | 未指定 | 対応エンコーダーの品質値です。 |
| Qmin / Qmax | 未指定 | 量子化値の下限・上限です。 |
| FPS | 未指定 | 出力フレームレートです。 |
| 復元前にFPS変換 | オフ | 復元処理へ渡す前にFPSを変換します。時間方向の情報も変わるため通常はオフです。 |

### FFmpeg詳細設定

「追加FFmpegオプション」には、プリセットで指定されないオプションを入力できます。

```text
-pix_fmt yuv420p10le -profile:v main10 -b:v 20M
```

入力した内容はFFmpeg引数として追加されます。エンコーダーと互換性のない設定は処理失敗の原因になります。まず空欄で処理できることを確認してください。

## 10. メモリタブ

| 項目 | 初期値 | 説明 |
| --- | --- | --- |
| 掃除間隔 | 1 | 指定した処理単位ごとに不要メモリを解放します。 |
| 掃除開始空き容量 | 4 GB | 空きメモリがこの値を下回った場合に積極的に解放します。 |
| MPSメモリ比率を指定 | オン | PyTorch MPSプロセスが使う統合メモリの比率を制限します。 |
| MPSメモリ比率 | 0.46 | 1プロセスあたりの基準です。並列数を増やす場合は特に注意します。 |
| MPSメモリ統計を記録 | オフ | 詳細調査用のメモリログを追加します。 |

スワップが増えて処理速度が低下する場合は、並列数を1へ戻し、最大クリップ長または復元チャンク数を小さくしてください。並列数を増やすことが常に高速化につながるわけではありません。

## 11. 設定タブ

「現在の設定をデフォルトに保存」を押すと、各タブの値を現在のmacOSユーザー用設定として保存します。次回起動時に自動適用されます。

- 「保存済みデフォルトを読み込み」: 保存した値を現在の画面へ再適用します。
- 「初期値に戻す」: 保存値を削除し、工場出荷時の値へ戻します。
- ログ、進捗、実行中状態は保存されません。
- 入力・出力パスも保存対象です。外付けドライブを取り外した場合は選び直してください。

## 12. 独立アプリ「Mioh Upscaler」

動画全体の解像度を上げる機能はmioh本体から分離され、独立した
`Mioh Upscaler.app`として配布されます。miohの復元処理とアップスケールを
別々に起動・更新でき、モデルや一時領域も独立します。復元タブの
ROIエンハンサーとは異なり、出力動画そのものが指定解像度になります。

| モデル | 特徴 |
| --- | --- |
| FlashVSR Tiny | 動画用の時間整合モデルです。85フレーム単位のセグメントを共有デコードし、セグメント内のタイルを処理します。 |
| AdcSR | 軽量な1-step拡散系画像SRです。128px入力・4倍出力のFP32 Core AIモデルを使用します。 |

AdcSRは入力を128pxタイルへ分け、隣接タイルを16px重ねます。各タイルの
4倍出力はmmap上の1フレームキャンバスへfeather blendされ、全タイルの
合成後に動画フレーム全体で色を合わせます。85フレームを保持せず、入力は
1フレームずつ共有デコードするため、メモリ使用量は主にCore AIモデルと
4倍RGBA32Fキャンバスで決まります。

「optical flowで時間方向を安定化」をオンにすると、前フレームの高周波残差を
現在フレームから前フレームへのoptical flowでwarpし、低解像度フレーム間の
画素差から求めた信頼度を掛けて弱く混合します。低周波成分と色は現在
フレームのAdcSR結果を維持します。初期値は12%です。動きの速い素材や
シーン切り替えで残像が出る場合は値を下げるかオフにしてください。

AdcSRは常に4倍で推論します。2倍または任意解像度を選んだ場合は、全タイルの
合成後にLanczosで指定解像度へ変換します。処理中はフレーム番号、タイル番号、
optical flow、合成・書き込みの各段階が進捗に表示されます。Core AI実行には
macOS 27以降が必要です。独立アプリは実測進捗から経過時間と残り時間の目安も
表示します。推論開始直後の目安は変動が大きいため、数フレーム完了後の値を
確認してください。

## 13. 再生タブ

再生タブの動画選択は、処理用の「基本」タブとは独立しています。

### 通常動画

- 動画を選び「再生」を押します。
- 「処理前」をオンにすると元動画、オフにすると復元プレビューを表示します。
- 「バッファ上限」は1秒から60秒です。値を増やすと再生開始まで時間がかかりますが、処理速度の変動に強くなります。
- シーク後は新しい位置からバッファを作り直します。
- 復元プレビューには、復元タブのモデル・合成・ROIエンハンサー設定が反映されます。

### VR動画

miohはファイル名、コンテナメタデータ、縦横比からVR180・360・SBS・上下形式を自動判定します。VRと判定した場合だけ次の操作が表示されます。

- 表示: VR180または360
- 形式: Mono、SBS左右、上下
- 目: 左目または右目
- 視野角: 45度から105度。初期値は60度

現在のVR再生は元動画を直接再生し、復元モデルを読み込みません。8K HEVCで`hev1`のためAVFoundationが拒否する動画は、元ファイルをコピーせず、ローカルの仮想コンテナで`hvc1`としてストリーミングします。動画データはMac外へ送信されません。

「設定を反映して再開」は現在位置から表示・バッファ設定を読み直します。左右が逆の場合は「目」を切り替えてください。

## 14. ログタブと再開

進捗行は同じワーカーごとに更新され、ログが大量の改行で埋まらないように表示されます。エラーが起きた場合は、赤い要約だけでなく直前のログも確認してください。

処理を再開しやすくするには、次の設定を使用します。

- 「一時ファイルを保持」をオン
- 「処理済みセグメントを削除」をオフ
- 「強制的に再分割」をオフ
- 「既存結果を上書き」を必要な場合だけオン

既存の処理済みセグメントが正常なら、次回は未処理分だけが対象になります。

## 15. 推奨設定例

### 安全な初回設定

- 並列数: 1
- デバイス: MPS
- FP16: オン
- 自動最適化: オン
- Temporal overlap: 8
- クロスフェード: オン
- 合成効果: 境界フェザー1、その他0
- ROIエンハンサー: none
- 出力: hevc-apple-gpu-balanced
- MPSメモリ比率: 0.46

### 品質を少し強める

- シャープ: 0.15
- ディテール: 0.10
- スムージング: 0.10から0.15
- Temporal overlap: 12から15
- ROIエンハンサー: 必要な場合だけ強度0.2から0.4

映像によって適切な値は異なります。同じ10秒程度の区間を使い、元動画、初期値、変更後を並べて比較してください。

## 16. トラブルシューティング

### 開始ボタンを押せない

「基本」タブで入力と出力の両方を選択してください。

### Core AIモデルを選べない

Core AIモデルにはmacOS 27以降が必要です。macOS 26では`basicvsrpp-v1.2`とCore ML検出モデルを使用してください。macOS 27以降でも一覧に出ない場合は、2.1節の変換コマンドの終了コードと最後のエラーを確認し、2.2節のモデルファイルを確認してください。

### ダウンロードや変換に失敗する

モデル取得が失敗した場合は、ダウンロードスクリプトの最後に表示される失敗一覧を確認し、同じコマンドを再実行します。SHA-256不一致の場合はファイルを使わず再取得します。変換時に`missing packaged Python`が出た場合は、アプリ内の`Contents/Resources/runtime/bin/python3.12`を確認してください。古いアプリからruntimeだけを移植せず、正しいUniversal版をインストールし直します。macOS 26で`--coreai-only`を指定すると失敗します。

### メモリ不足・極端に遅い

1. 並列数を1へ戻します。
2. ほかのGPU・MPSアプリを終了します。
3. 最大クリップ長または復元チャンク数を小さくします。
4. 一時ディスクの空き容量を確認します。
5. MPSメモリ統計をオンにしてログを確認します。

### セグメント処理が最初から始まる

「強制的に再分割」がオフであること、一時ファイルが残っていること、入力・分割条件・保存先が前回と同じであることを確認してください。

### 出力の境界が目立つ

境界フェザーを少し増やし、Temporal overlapを8から15の範囲で増やします。シャープやディテールが強すぎないかも確認してください。

### 色味や肌の質感が変わる

ROIエンハンサー強度、テクスチャ、ディテール、シャープを下げます。まずROIエンハンサーをnoneへ戻し、どの処理が原因か一つずつ確認してください。

### VR動画が黒画面または再生失敗になる

- 表示形式と左右・上下形式が合っているか確認します。
- 視野角を60度へ戻します。
- 外付けドライブが十分な速度で接続されているか確認します。
- 8K動画ではバッファを20から30秒へ増やします。
- ログの「AVFoundation」「hev1」「hvc1」に関する行を確認します。

### 停止後に再開したい

一時ファイルを削除せず、同じ入力・出力・分割条件で再実行します。処理済みセグメントの検証後、残りだけが処理されます。
