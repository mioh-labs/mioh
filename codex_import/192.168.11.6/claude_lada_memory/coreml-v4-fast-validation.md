On 2026-07-05, implemented the v4-fast Core ML validation plan (docs/superpowers/plans/2026-06-18-v4-fast-coreml-validation.md) on branch `apple/v4-fast-coreml-validation`: export script, validation harness, postprocess contract doc. Parity smoke passed (box diff 2.69px, conf diff 0.0023, mask area diff 1.0%).

Merged to main (fast-forward, b21d99b) on 2026-07-05. The mlpackage is committed to git in model_weights/ (15cbb6d) after an untracked copy silently vanished and broke the `v4-fast-coreml` name; `--mosaic-detection-model v4-fast-coreml` works everywhere. The parallel wrapper now prints the worker output tail on failure (its filter used to swallow errors like "Invalid mosaic detection model"). Detection is pinned to CPU+ANE (LADA_COREML_COMPUTE_UNITS overrides) because Core ML's Metal compile of this model intermittently crashes (MPSGraph MLIR assertion). Note: `codex/v4-fast-coreml-validation` is a much larger unmerged parallel effort (Apple restoration backend); merging it later will conflict with these files.

Same day, integrated Core ML detection into the runtime (commit "Run mosaic detection via Core ML on Apple Silicon"): `Yolo11CoreMLSegmentationModel` (AutoBackend, CPU tensors, square letterbox, per-frame loop since AutoBackend's Core ML branch is batch-1 only), selected automatically for `.mlpackage` paths; model name `v4-fast-coreml`. Measured: detection 13.1 ms/frame vs 79.3 ms/frame torch/MPS (~6x), end-to-end CLI 14% faster on a 4s 1080p60 clip.

Restoration profiling (2026-07-05, commit be9dd1f): found flow_warp on MPS ran NaN/Inf `.any()` checks per call = full GPU sync ×~200 per 18-frame clip. Gated behind LADA_MPS_VALIDATE_TENSORS (default off): restoration 82.6→51.0 ms/frame (-38%), bit-identical output. Added LADA_BASICVSRPP_PROFILE=sync for true per-stage GPU timings. Post-fix breakdown per 18-frame clip (~1.0s): backbone 33%, deform_align 26%, upsample 12%, flow_warp 10%, SPyNet 6%. Pipeline wall time only improved 34.1→31.8s on the 4s test clip — the rest was GIL-bound CPU work. Second round (82ae6ce): restored clips handed to composition as CPU tensors (batched transfer, MPS lock skipped for CPU composition), create_blend_mask via cv2.blur (4.1→0.2ms), YOLO mask conversion without int64 intermediates. 4s clip: 30.7→23.2s (-24%); cumulative from torch-detection baseline 39.7→23.2s (-42%). Ruled out: double decode (~2.4s total), encoder choice (VT ≈ x264 wall), max-clip-length (no throughput effect; only affects first-frame latency). Startup ~7s model load + first-clip latency dominates perceived stalls. Output differs from pre-optimization only by blend-mask float rounding (PSNR ~49dB).

Real-ESRGAN 4x ROI enhancer (2026-07-05, ecfb9ea): Core ML/ANE backend (scripts/apple/export_realesrgan_coreml.py + lada/restorationpipeline/coreml_realesrgan.py), selected by .mlpackage path. 301 ms/frame on ANE vs 1763 ms torch/MPS fp32 (fp16 only 1573 — memory-bound); PSNR 57.2 dB vs fp32. 4s clip with 4x enhancement: 98.8 s end-to-end (fp32 torch never finished, 40+ min). Weights model_weights/RealESRGAN_x4plus.pth downloaded from official release; export at model_weights/RealESRGAN_x4plus_256.mlpackage (untracked). Inspired by jasna's secondary restoration (unet-4x equivalent).

MewZoom alternative enhancer (f7ebe43, 7926aad): CoreMLROIEnhancer generalized (metadata-driven, any lada.enhancer .mlpackage). MewZoom-V1-4X-Unet (Apache-2.0, 128M UNet, HF andrewdalpino) via scripts/apple/export_mewzoom_coreml.py. ANECCompile crashed on decoder upsample1 (conv→1536ch→pixel_shuffle; conv alone OK, shuffle alone OK, fused pattern crashes) — worked around by chunking the shuffle into 2 channel groups (bit-identical since PixelShuffle consumes contiguous r² channel groups). Result: 100 ms/frame on ANE (was 793 CPU-fallback), faster than Real-ESRGAN 299 ms; 4s clip end-to-end 52.3 s. Visual: MewZoom denoises/softens, Real-ESRGAN sharpens more — choose per source. The chunked-shuffle trick likely applies to any big subpixel-conv model. Caution: plain `pip install mewzoom` downgrades torch to 2.9.x (pin torch~=2.9); install with --no-deps and keep torch 2.12.
